# 联机竞速（2026-10-04）

用户要求加入联机功能，以便邀请别人一起竞速。这超出了「纯静态单机」的 MVP 边界，用户于 2026-10-04 明确选择了以下方案：

| 决策 | 选择 |
| --- | --- |
| 胜负规则 | 同图生存比分：同一种子、同时出发，所有人失败后按分数排名 |
| 服务端 | 现有 RackNerd VPS 上的 Node WebSocket 房间中转，经 Caddy 反代为 `wss://game.norliva.top/ws` |
| 房间与身份 | 最多 4 人；自动分配橘猫/灰猫/黑猫/白猫代号；不收集昵称或任何用户数据 |

## 玩法流程

1. 开始或失败界面点「邀请好友竞速」，创建房间并获得 5 位房号，地址栏同步为 `?room=房号`。
2. 好友打开邀请链接即可加入；房主点「开始比赛」，所有人收到同一个随机种子并开始 3 秒倒计时。
3. 倒计时结束后，每个人在自己的浏览器里跑同一张地图，对手以半透明、带颜色标签的「幽灵猫」显示，跑出画面时在屏幕边缘显示同色箭头；右上角是实时排名。
4. 先失败的人看到「等待其他小猫…」和实时分数；全部结束后显示排名（冠军 / 第 N 名），房主可以「再来一局」。
5. 比赛中途加入的人会标记为「下一局」，等下一局开始时一起出发。

## 架构

- **规则层不变**：联机只是把服务器下发的种子注入现有的 `GameSession`。同种子同输入完全确定，所有人看到相同的楼顶和障碍，不需要同步世界状态。
- `shared/race-protocol.ts`：前后端共用的 JSON 消息格式和校验。数值有上下界，消息上限 512 字节；客户端也把服务器消息当作不可信输入。
- `server/race-room.ts`：纯逻辑的房间状态机（大厅 → 倒计时 → 比赛 → 结算），时钟和随机数可注入，不做网络 I/O。
- `server/race-server.ts`：WebSocket 接线，负责 Origin 白名单、`/ws` 路径、全局 400 连接和每 IP 8 连接上限、每连接每秒 30 条消息的限流、20 秒心跳。在 Cloudflare 之后只信任来自本机反代的 `CF-Connecting-IP`。
- `src/net/race-client.ts` / `race-controller.ts`：浏览器端连接、房间视图、倒计时（本地时钟）、每 100ms 节流上报位置和分数、幽灵猫缓冲（延迟 150ms 插值，对象复用）。
- `src/ui/race-panel.ts`：房间、倒计时、等待、结算界面和实时排名；全部用 `textContent` 构建 DOM。
- 比赛最长 15 分钟，超时按已上报分数强制结算，避免挂在后台的玩家卡住房间。离开的选手退出排名；房主离开后自动移交给剩下编号最小的玩家。

## 信任模型与隐私

- 面向朋友之间的休闲竞速：分数由客户端上报，服务器只做格式和范围校验，**不能防作弊**。这不是排行榜，也不复用于将来的 M5 全球排行。
- 服务器只在内存里保存房间，不写盘、不记日志、不存 IP 以外的任何信息；IP 只在内存中用于连接计数，断开即删除。房间清空即删除。
- 暂停仍然遵守「后台自动暂停、显式继续」。由于按分数（距离）排名，暂停不会带来优势；对手会继续跑，你的幽灵猫停在原地。倒计时结束时页面若在后台，开跑后立即进入暂停。

## 依赖

- `ws@8`：服务端唯一的运行时依赖，约 150KB，零依赖，是 Node 生态最常用的 WebSocket 实现，不会打进前端包。Node 自带的只有 WebSocket 客户端，没有服务端实现。
- `@types/ws`、`@types/node`：仅用于开发时的类型检查。
- VPS 使用 Debian 官方源的 `nodejs` 包，可以随系统安全更新。

## 验证

- 新增单测：协议校验 3 项，房间状态机 5 项（建房/加入/满员、只有房主能开赛、倒计时、状态转发、排名与再来一局、中途加入观战、离开与房主移交、超时结算、房间上限），真实 WebSocket 集成 3 项（完整一局、Origin/路径拒绝、IP 上限/坏消息/限流），浏览器端控制器 3 项（连接后发送、种子只交出一次、上报节流、幽灵插值、断线）。联机新增 14 项，全部 87 项通过。
- 本地浏览器（Vite 代理 + 本地中转）实测：标签页 A 建房，B 通过邀请链接加入，双方玩家列表、房主标签、按钮状态正确；房主开赛后两边同时显示倒计时「3」。
- 未验证：Chrome 窗口处于后台导致动画帧暂停，倒计时之后的实际同场奔跑、幽灵猫显示和结算界面没有在浏览器中实测；手机真机和跨网络对战也未测，需要在生产站用两台设备试玩确认。
