# 路障与鱼干（2026-10-03）

用户反馈元素少，并明确选择「两者都要：障碍和奖励结合」。本轮增加真正参与模拟的路障和收集，不再只提高跑速。

## 玩法

- 红色条纹挡板：24×20 逻辑像素，碰到即结束。斜纹与整块实体轮廓用于区别无碰撞的通风口、天线等装饰；失败界面明确提示路障原因。
- 金色鱼干：16×10 逻辑像素，每个 +5 分，碰到后消失且只记一次；HUD 与结算显示收集数量。静音关闭时有短收集声。
- 普通平台间隙上方放置 1 个鱼干；障碍上方有 3 个鱼干组成弧线。收集并非继续游戏的条件。
- 单次跳跃、100ms 缓冲、60ms 离边容错、办公外观和暂停隐藏保持不变。

## 生成与安全余量

- 起始屋顶和前两座新屋顶无障碍；从 id=3 开始每四座出现一个障碍屋顶，基础进度 500+ 后可增加到每两座一个。
- 障碍屋顶宽度 340 逻辑像素；障碍距左缘 120–144px，右侧至少 172px，可先越障落地再起跳跨缝。障碍屋顶不叠加普通装饰。
- 位置仅由种子平台序列、平台 ID 和基础进度决定，与视口、时间或渲染无关。
- 鱼干计入总分，速度仍依基础进度分（距离与落地奖励）变化，避免加分直接改变当前跳跃速度；前方生成也使用同类基础进度估算。
- 障碍与奖励使用扫掠矩形判定，覆盖高速跨过整个对象的情形；致命帧优先判定障碍，不在同帧继续捡奖励。
- 收集标记随所属平台裁剪；总计数为数字，重开归零并重新生成奖励。失败后会话停止推进。

## 验证

- 53 项单测：包含 24,000 次生成可达性、300 种种子的 60 秒避障长局、三次 180 秒长局、跨视口同输入一致性，以及高速碰撞、越过障碍不误判、奖励可获得/不重复计分/重开恢复。
- 生产构建本地浏览器实际操作：连续跳过前三处间隙、越过第一处路障，收集计数到达 7；暂停/继续和指针跳跃正常。
- 360×640、390×844、430×932、1366×900 四视口检查通过，控制台无错误；路障与鱼干对浅底对比大于 4:1。
- TypeScript、生产构建通过；零新增依赖。

实机 iPhone Safari、Android Chrome 和低端设备帧时间尚未复验。本地最高分继续保留；新增收集加分后与旧版最高分不具有严格可比性。
